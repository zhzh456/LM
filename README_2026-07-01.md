# Budget Training Loss (2026-07-01)

Current training loss:

`L = L_CE + λ * mean_h(r_h)`

Where:

- `L_CE`: normal task CE loss
- `r_h`: token retention ratio (budget ratio) for each head
- `\lambda`: regularization coefficient (currently default `0.01`)

In short, the current implementation is:

normal CE + regularization coefficient * average token retention ratio across all heads.

## Parameterization Notes

The trainable parameter is not the budget ratio directly. It is a `logit`.

At each forward pass, it is converted to the real retention ratio `r` in two steps:

1. `r0 = sigmoid(logit)` to map into `(0, 1)`
2. map to configured range `[lo, hi]` (default `[0.01, 1.0]`):

`r = r0 * (hi - lo) + lo`

So:

- very negative `logit` -> `r` approaches `lo` (sparser)
- very positive `logit` -> `r` approaches `hi` (denser)

Why this parameterization:

- optimization is easier with unbounded trainable variable (`logit`)
- final `r` always stays in a valid range (will not be `<0` or `>1`)

## Default Values

- `lo = 0.01`
- `hi = 1.0`
- `init_ratio = 0.3` (from `--budget_init_ratio 0.3`)

Trainable parameter initial value:

`logit_0 = logit(0.3) ~= -0.84729786`

## Where STE Is Used

Current STE is applied in `train/patch_sparse_attn.py` for the budget top-k implementation:

- function: `_budget_topk_attention_forward_ste()`
- only used in training branch when `train_sparse_budget=True`
- called from `_patch_attention_forward(...)`

Key STE-lite code:

```python
# STE-lite surrogate: keep hard top-k forward path, provide ratio gradient
# without materializing extra full (B,H,Q,K) softmax tensors.
attn_weights = weights_hard + (weights_hard * (ratio_bhq1.to(query.dtype) - ratio_bhq1.to(query.dtype).detach()))
attn_weights = F.dropout(attn_weights, p=dropout, training=module.training)
value_states = repeat_kv(value, module.num_key_value_groups).to(query.device)
attn_output = torch.matmul(attn_weights, value_states)
attn_output = attn_output.transpose(1, 2).contiguous()
return attn_output, weights_hard, attn_scores
```

Meaning:

- top-k itself is still hard `torch.topk(...)` selection
- STE is the straight-through `... - ...detach()` term above
